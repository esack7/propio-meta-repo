# Implementation decisions

Recorded October 11, 2026 and updated October 12, 2026 (America/Los_Angeles). Implementation is merged and published in providers `0.6.0` and agent `1.4.0`. Feature and POC worktrees are closed; retained branches preserve implementation and POC source, and POC credentials remain outside the repositories.

## Provider boundary

`OpenAiAuthConfig` is an additive union: `{ mode: "api-key" }` or `{ mode: "chatgpt", accountId }`. Missing `auth` retains the existing API path. ChatGPT configurations reject an API key. The synchronous factory takes an optional sixth `ProviderRuntimeOptions` argument whose account-specific source obtains an access token before each attempt. The provider has no storage paths, browser flow, registry discovery, or API fallback. The application binds the source to an immutable registration ID, not an email or mutable default.

The subscription adapter uses public Responses, developer instructions, local namespaced functions, full transcript/opaque continuation replay, `stream: true`, and `store: false`. Only `response.completed` admits buffered tool calls and terminal success. Failure, incomplete, malformed stream, EOF, abort and idle timeout stop admission. An open reader is cancelled at completion. Context length keeps the existing typed recovery contract. Admission retries require recognized temporary codes or a generic typed HTTP 429 rate limit; plan usage limits and ambiguous inference transport failures are not replayed. Images remain explicitly disabled.

PR #17 review follow-up preserves typed generic HTTP authentication, model-not-found, invalid-request, capacity and rate-limit errors with safe code/param/status/request-ID metadata. Invalid subscriber context is also an authentication error, including inside SSE. Upstream messages/causes are replaced with fixed safe text before standard status translation. Documented `subscription_sharing_usage_unavailable` and `subscription_sharing_user_unavailable` codes support bounded pre-stream retries; streaming failures never restart inference. Failure-event usage is captured before rejecting the event without dispatching pending tools or reporting successful completion.

Subscription idle timeout defaults to five minutes between chunks and is configurable using `OpenAiSubscriptionOptions.idleTimeoutMs` or `ProviderRuntimeOptions.openAiSubscription.idleTimeoutMs`; valid values are positive integer milliseconds up to the Node timer maximum. Caller cancellation retains its original reason on the subscription path. Legacy API Responses providers retain their translated cancellation behavior and have no subscription idle guard. A valid application token function prevents all API-key environment reads; JavaScript callers with a missing/non-function source fail closed. The additive factory signature is retained; an ergonomic options-object overload is outside this focused review fix.

## Storage and concurrency

The application owns OAuth and token rotation. `jose` 6.2.12 verifies signed identities. `@napi-rs/keyring` 2.1.1 is lazy-loaded and stores the complete secret record in one entry. Linux explicitly selects Secret Service instead of falling back silently to kernel storage. `os-lock` 2.0.0 supplies a kernel-released lock on a permanent per-registration inode; an in-process guard handles process-owned fcntl semantics. No lock age, PID reuse, or stale-file deletion decides ownership. These native dependencies are optional so an API-only install does not depend on a credential backend. Missing locking fails closed for credential operations.

Registry metadata lives under `~/.propio/auth/openai`; secret records contain access/refresh/ID tokens and generation. Stable host ID and immutable client/subject binding survive logout. Explicit `--storage protected-file` stores secrets under `~/.local/share/propio/openai-secrets`, outside the sandbox configuration mount. Unix paths enforce owner-only directories/files, no symlink leaves or hardlinks, atomic replacement, and fsync. Windows credential operations fail closed until private ACL handling is implemented and verified; Windows support is not claimed.

Before rotating remotely, metadata records `refreshing`. A newer durable secret generation can recover a failed metadata commit. Transient network, timeout, cancellation, and empty server-error responses before confirmed rotation preserve the token set. A malformed successful token response or failure after remote rotation requires reauthorization rather than reuse of an uncertain refresh token. A returned refresh ID token is verified against the same client/subject. Logout first blocks new credential acquisition, then performs bounded revocation attempts and local deletion; an unconfirmed remote result is reported. Local `/account` logout cancels the selected registration’s foreground request and pending summary and discards aborted summary results. Already admitted requests in another process cannot be recalled.

Browser authorization holds a separate sign-in lock. The credential lock covers only the initial snapshot and final commit, which rereads state and rejects intervening logout or registration changes. Token exchange and identity verification still run inside the commit lock; unusually slow network requests can exceed another caller's 15-second lock wait. This nonblocking improvement is deferred.

macOS Keychain whole-record replacement/read/delete and real independent-process lock contention/SIGKILL recovery passed. Linux Secret Service and Windows native gates were not run. No actual POC credential migration was performed. Migration is explicit, same-host, uses both lock protocols, stages a blocked destination, retires only the selected source, then activates the destination.

## Discovery, selection, sessions

Model discovery validates the current documented `models`, `slug`, `display_name`, and `visibility` fields, filters `visibility: list`, and keeps server order. The five-minute cache is keyed by registration and credential generation, rechecks credentials before returning, and fails safely on invalid catalogs. Catalog fields are not evidence of context capacity. Setup and newly discovered models preserve configured budgets, otherwise resolve an exact-ID table of documented model limits. Unknown IDs require user-supplied capacity or a visibly selected conservative 128000-token budget; selected budgets live in `providers.json`, and documented source URLs/check dates live in the exact-ID table. The unused budget sidecar was removed.

The user authorized documented defaults after testing locally. Limits were checked on October 11, 2026: `gpt-6.1-sol`, `gpt-6-astra`, `gpt-6-sol`, `gpt-6-luna`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna` have 1,050,000 context, 922,000 input and 128,000 output tokens. `gpt-5.5` and `gpt-5.5-2026-04-23` document the same context/output limits but no separate input limit. Each table entry records its official model URL and check date. No prefix matching or unverified catalog field is used; future snapshots require evidence before inheriting limits. [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [GPT-5.5](https://developers.openai.com/api/docs/models/gpt-5.5).

The legacy provider `contextWindowTokens` field is an effective working ceiling. Automatic selection takes the smaller of documented input and context minus maximum output (922,000 for these entries); the planner subtracts its additional reserve. This is local budgeting, not an unsupported request output parameter or a subscription entitlement claim. Saved per-model budgets take priority within the same immutable registration. Setup and `/model` expose an explicit adjustment before session/default scope selection; `documented` resets an existing budget, numeric values override it, and `conservative` remains opt-in. API setup behavior and the provider contract stay unchanged. Dynamic capacity lookup remains unavailable until the subscription catalog exposes verified capacity semantics.

Sign-in does not alter billing/defaults. Setup and `/model` explicitly choose session or persistent scope. Failed default persistence retains a usable session selection and reports that the saved default was unchanged. Cross-registration selection starts a new conversation by default; explicit transcript transfer strips provider-specific opaque continuation. Safe optional account/mode references bind sessions. Background summaries remain pinned to their original provider; results are discarded after a provider revision change. Summaries disclose consumption of plan allowance or permitted credits.

Both `/model` and `/account setup` ask before changing access/account, including leaving ChatGPT for API access; cancel leaves selection and transcript unchanged. `/model` keeps session settings when a provider name also exists on disk, while listing newly saved providers. Saving rereads disk and changes only the chosen subscription model; other session entries are not persisted and a changed saved account binding is refused. Edits to an existing disk provider become available after restart. This preserves explicit session choices without overwriting unrelated saved configuration.

## Sandbox feasibility

Use a private per-run loopback HTTP broker instead of exposing the OS store or renewable token files. A random capability permits only bounded GET `/token` for one registration. Host-owned access-token acquisition performs renewal; the container receives access tokens only. The container gets a filtered read-only configuration view excluding production auth and legacy POC directories, and a separate read-only broker descriptor. Symbolic links are excluded from the view. Environment carries the descriptor path, not tokens or capability. Shutdown, signals, and owner loss tear down the broker/view. The hard eight-hour lifetime was removed so a running sandbox keeps its scoped broker and configuration.

Actual macOS/Colima Docker transport passed with dummy renewable access-token responses and a rejected alternate account. Temporary mounts must live under the user home directory; Colima did not share the macOS `/var/folders` temporary path. Native Linux and Windows subscription sandbox startup is explicitly blocked pending transport verification. Docker Desktop and a real long-running subscription sandbox remain pending; this is a macOS transport preview, not full sandbox acceptance.

Missing configuration passes through to ordinary CLI guidance; the wrapper's existing missing-`~/.propio` check remains. Invalid sandbox configuration fails with sanitized guidance. Missing defaults are named by recognizing the pinned provider library's validation message; unknown wording falls back to generic configuration guidance. A typed library error would make that diagnostic more robust in a future update.
